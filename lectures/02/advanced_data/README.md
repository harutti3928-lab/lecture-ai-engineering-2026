# 発展課題：用語集Q&Aデータセット

`prepare_advanced.py` が公式の `scripts/make_sft_dataset.py` を実行して作成した。
対象は `glossary_snapshot.json` の65項目（講座用のたたき台の用語集）であり、外部情報の正しさを検証したデータセットではない。

- `glossary_sft.jsonl`：公式スクリプトが出力した130件のQ&A。そのまま保存。
- `train.jsonl`：各用語の1つ目の質問テンプレート、65件。
- `valid.jsonl`：各用語の2つ目の質問テンプレート、65件。
- `evaluation.jsonl`：学習・検証とは別に作成した26問と正解・採点条件。
- `manifest.json`：作成方法、件数、用語集と生成スクリプトのSHA-256。

学習・検証用には同じsystem指示を加え、回答は元の定義文のままとした。今回はJSON形式の学習ではなく、用語の定義を日本語の文章で答える実験である。未知語の拒否回答は学習データに追加していない。

評価は用語名を含む質問10問、別名または説明で言い換えた質問10問、用語集にない語6問からなる。対象の既知10概念の定義は学習に含まれるため、これは未知の質問文への対応と定義の再現の実験であり、未学習概念の汎化性能の実験ではない。学習・検証・評価の質問文が重複しないことを生成時に確認している。

既知語の採点は、指定した概念ごとのキーワード群がすべて含まれ、回答を拒否していないことを条件とする。各群の中の表現はOR条件で、元の定義が合格することを事前に検証した。未登録語は「記載がない」「確認が必要」などの明示的な確認要求・回答保留を条件とする。これは用語集の範囲に沿った応答を測るルールであり、未登録語について一般知識で正しく説明した回答でも不合格になる。キーワード採点は意味全体の正しさを保証しないため、評価JSONの回答原文と照合する。

用語集検索では、質問文に現れる3文字以上の用語名・別名・IDのうち最長のものを検索語とし、該当がなければ質問文全体を渡す。既存の `app.tools.search_glossary` の先頭ヒットの定義を回答し、ヒットがなければ確認要求を返す。検索処理には評価用のterm_idや正解を渡さない。LLMによる検索語の抽出や回答生成、ベクトル検索は行っていない。

再現コマンド（リポジトリ直下、出力が存在する場合は上書きを防ぐため停止する）：

```powershell
.venv/Scripts/python.exe lectures/02/prepare_advanced.py
.venv/Scripts/python.exe -u lectures/02/run_advanced.py
```

モデルのadapterとチェックポイントは `lectures/02/local_runs/advanced/`、評価・実行記録は `lectures/02/results/advanced/` に保存する。
