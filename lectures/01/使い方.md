# Git・GitHubの使い方：この講座での確認・切り替え・提出

## 今、どのブランチのファイルを見ている？

このメモを作成した時点（2026-10-30）では、ローカルの作業ブランチは `lec01`。
VS Codeで開いた `lectures/01/answer.md` も、基本的には現在のブランチを土台にした作業フォルダのファイルを表示している。

ただし、編集してまだコミットしていない内容も表示されるので、「画面の内容がすべて `lec01` に保存済み」という意味ではない。
エディタの保存はPC上のファイルへの保存、コミットはGitへの記録、pushはGitHubへのアップロードで、それぞれ別の操作。

### ターミナルで確認する（確実な方法）

VS Codeの「ターミナル → 新しいターミナル」を開き、次を実行する。

```powershell
cd C:\dev\lecture-ai-engineering-2026
git branch --show-current
```

`lec01` と出れば、現在選択しているブランチは `lec01`。
次のコマンドでは、ブランチ一覧の現在位置に `*` が付く。

```powershell
git branch
```

表示例：

```text
* lec01
  main
```

変更の状態も一緒に見るなら、次を使う。

```powershell
git status --short --branch
```

表示例：

```text
## lec01...origin/lec01
 M lectures/01/answer.md
```

先頭の行は現在のブランチと追跡先。`M` は変更あり、`??` はGitにまだ登録していないファイルを表す。`git status` だけなら、さらに詳しく読める。

### VS Codeの画面で確認する

通常、ウィンドウ左下のステータスバーに `lec01` などのブランチ名が表示される。クリックすると切り替え先を選べる。
見つからないときは上のターミナルのコマンドで確認する。

`lectures/01` はフォルダ名、`lec01` はブランチ名で、別のもの。
`main` にも `lectures/01` は存在するため、開いているファイルのパスだけではブランチは分からない。

## GitとGitHub、fork・branch・PRの関係

- **Git**：ファイルの変更履歴を記録し、ブランチを切り替える仕組み。PC上でも動く。
- **GitHub**：Gitのリポジトリをオンラインで保管し、PRなどを使って変更を共有できるサービス。
- **リポジトリ（repo）**：プロジェクトのファイルと変更履歴をまとめたもの。
- **fork**：GitHub上で、他の人のリポジトリから自分のアカウント用のリポジトリを作ること。講座では最初に自分用のforkを作り、その中で作業・提出する。
- **clone**：GitHub上のリポジトリを、履歴も含めてPCに取得すること。今開いているフォルダはローカルの作業場所なので、毎回cloneし直す必要はない。
- **branch（ブランチ）**：変更履歴を分けて作業するための名前。講座では `main` を土台に、`lec01` や `lec02` で各回の課題を進める。
- **commit（コミット）**：選んだ変更を、説明文付きの履歴としてローカルに記録すること。
- **push**：ローカルのコミットをGitHubへ送ること。
- **pull**：GitHub側の更新を取得して、現在のローカルブランチに取り込むこと。
- **PR（Pull Request）**：あるブランチの変更を、別のブランチへ取り込むための提案。PRを作っただけでは取り込みは完了しない。
- **merge（マージ）**：変更を取り込むこと。PRがOpenの間は、通常まだ取り込まれていない。

この講座では、次の流れになる。

```text
講座のリポジトリ（matsuolab）
  ↓ fork：GitHub上に自分用のリポジトリを作る
自分のfork（harutti3928-lab）
  main：取り込み先
  lec01：第1回の作業・提出用ブランチ
      ↓ PR：lec01の変更をmainへ取り込む提案
  main：マージ後は第1回の変更も含む
```

自分のfork：<https://github.com/harutti3928-lab/lecture-ai-engineering-2026>

`origin` は、このPCのGitに登録された送信・取得先の略称。このリポジトリでは自分のforkを指している。確認するには次を実行する。

```powershell
git remote -v
```

`main` はローカルブランチ、`origin/main` は最後に取得したGitHub側の `main` の状態を表す。自動で常に最新になるわけではない。

## mainに切り替える・lec01に戻る

**まず、編集内容をファイルに保存して `git status` を確認する。** エディタで未保存の内容はGitの確認に出ない。

```powershell
git status
```

コミットしていない変更がなければ、次で切り替えられる。

```powershell
# mainへ切り替える
git switch main

# 現在位置を確認する
git branch --show-current

# 第1回の作業に戻る
git switch lec01
```

`git switch` すると、同じフォルダの管理対象ファイルが選んだブランチの内容に切り替わる。ブランチごとに別のフォルダができるわけではない。
また、切り替えるだけでは `lec01` の変更は `main` に取り込まれない。

### コミットしていない変更がある場合

作成時点では `answer.md` の補足が未コミットで、追加PDFも未追跡だった。
このような変更は、ブランチを切り替えると次のブランチへ持ち越されることがある。変更が衝突する場合は、Gitが切り替えを止める。
**ブランチを切り替えれば編集が自動でそのブランチに保存される、とは考えない。**

第1回の変更として記録しておく場合は、`lec01` にいることを確認し、必要なファイルだけコミットする。

```powershell
git branch --show-current
git diff -- lectures/01/answer.md
git add lectures/01/answer.md "lectures/01/使い方.md"
git diff --cached
git commit -m "第1回: 実行方法とGitHubの使い方を補足"
```

この例ではPDFはコミット対象に含めていない。未追跡のPDFはフォルダに残り、通常は別のブランチでも見える。
`git add -A` はPDFを含む他の変更もまとめて登録するので、対象を確認してから使う。

まだコミットせず、一時的に編集前の `main` を見たいときは、変更を退避できる。

```powershell
# 未追跡ファイルも含めて退避する。退避対象は作業フォルダから一時的に消える
git stash push -u -m "第1回の作業を一時退避"
git switch main

# 見終わったら元のブランチに戻して、退避した変更を戻す
git switch lec01
git stash pop
```

`-u` は未追跡ファイルも退避する指定で、Gitが無視しているファイルは対象外。`stash pop` で競合が出た場合は、その内容を確認してから作業を続ける。

## 第1回のPRと、補足を追加する方法

2026-10-30に確認した時点では、次のPRがOpenだった。

[PR #1：第1回 演習・宿題：トークン表示と回答の比較](https://github.com/harutti3928-lab/lecture-ai-engineering-2026/pull/1)

- 取り込み先（base）：**自分のforkの `main`**
- 変更元（head / compare）：**自分のforkの `lec01`**
- 既に含まれていたもの：トークン表示の実装、基礎課題の比較実験と考察
- このメモの作成前には未反映だったもの：`answer.md` の操作方法の補足

上の手順で必要な変更をコミットしたあと、`lec01` から次を実行する。

```powershell
git push origin lec01
```

同じブランチのOpenのPRには、pushしたコミットが自動で追加される。補足のために別のPRを作り直す必要はない。
GitHubでPRを開き、**Files changed** から、提出したい内容が含まれているか確認する。

PRの作成とマージは別の操作。課題の提出指示は「PRを作ること」なので、提出のために自分でマージまで必要かは講座の案内に従う。
このメモを作る作業では、コミット・push・PRのマージは行っていない。

## PRがマージされたあと、mainを更新する

GitHubでマージされても、PCの `main` が自動更新されるわけではない。
未コミットの変更を先に記録・退避したうえで、次を実行する。

```powershell
git switch main
git pull --ff-only origin main
```

`--ff-only` は、履歴をそのまま先へ進められる場合だけ更新する指定。止まった場合は、ローカルとGitHubの履歴を確認する。
PRがまだOpenなら、これを実行しても未マージの `lec01` の変更は入ってこない。

第2回を最新の `main` から始める場合は、更新したあとで作業ブランチを作る。

```powershell
git switch -c lec02
```

`-c` は新しくブランチを作る指定。既に `lec02` がある場合は `git switch lec02` で切り替える。

## 次の課題を提出するときの基本の流れ

1. `git status` と `git branch --show-current` で、現在位置と変更を確認する。
2. 未コミットの変更を整理し、課題の土台にする `main` を更新する。
3. 回ごとのブランチを作る（例：`git switch -c lec02`）。
4. 課題を進め、`lectures/02/answer.md` などを編集して保存する。
5. `git diff` で変更を確認し、提出するファイルを `git add` してコミットする。
6. `git push -u origin lec02` でGitHubへ送る。
7. 自分のforkで、**base: main / compare: lec02** のPRを作る。base repositoryが講座元ではなく自分のforkであることを確認する。
8. PRの **Files changed** を開き、回答や必要なコードが含まれているか確認する。

GitHubのファイル画面にもブランチの選択欄がある。ただし、GitHub上で選んだブランチと、VS Codeのローカルで選んだブランチは連動しない。画面ごとに現在位置を確認する。
